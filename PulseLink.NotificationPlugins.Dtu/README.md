# PulseLink DTU plugin

DTU SMS / 语音网关插件。DTU 主动连接 TCP 监听端口后，插件以 GBK 编码发送 `phone:type:content` 指令：短信为类型 `0`，语音/TTS 为类型 `3`。

## 投递与确认语义

- 所有通知进入共享 FIFO 队列；每台在线 DTU 都有独立 worker，同一设备同一时刻仅处理一个任务。
- 未写入设备前连接断开时，任务会回到队列；已写入设备后绝不自动重发，避免重复短信或电话。
- SMS 与 TTS ACK 会被解析为成功、失败或进度；设备断线或超时后的任务标为 `Unknown`，宿主收到 `Accepted/DtuAckPending`，不会立即重试。
- `Unknown` 任务在 5 分钟内可由同一来源 IP 的 DTU 重连后的迟到 ACK 修正为成功或失败。
- 同一来源 IP 存在待确认任务时暂停向其下发新任务，避免无任务 ID 的迟到 ACK 错配到新任务。
- TTS 协议中的 `tts busy` 是拨号进度，`TTS speack` 表示已接通并开始播放，`ready` 表示播放结束。
- 网关事件通过宿主插件日志记录，并携带投递 ID 以便与系统投递记录关联。

## 配置与系统集成

网关参数只有一个来源：**插件控制台**。短信和语音渠道实例仍然需要各创建并启用一个，以连接通知策略、收件人和模板；两种渠道均声明最多一个实例，渠道配置 JSON 应保持 `{}`。旧部署中的渠道级 DTU JSON 仅作为首次保存前的兼容性回退。

控制台可查看在线设备、设备上报日志、投递队列和历史任务；可取消尚未下发的任务，并清理已结束的任务记录。

打包：`./Pack-Plugin.ps1`。在 `PulseLink:Notifications:Plugins:AllowedPluginIds` 中加入 `pulselink.dtu`，随后在“通知中心 → 插件”上传 ZIP、创建并启用 `sms` / `voice` 渠道实例，再通过“插件控制台”配置网关。
