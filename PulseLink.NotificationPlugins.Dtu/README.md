# PulseLink DTU plugin

DTU SMS / 语音网关插件。DTU 主动连接 TCP 监听端口后，插件以 GBK 编码发送 `phone:type:content` 指令：短信为类型 `0`，语音/TTS 为类型 `3`。

## 支持的 DTU 模块

本插件支持的 DTU 模块为 **311@网口TTS 三网通**，用于短信和语音/TTS 通知。选购时请核对该型号及规格。

- [商品页面（淘宝，商品 ID：716914767847，规格 ID：5215744451589）](https://item.taobao.com/item.htm?id=716914767847&skuId=5215744451589)
- [模块参考资料（天猫附件）](https://itemcdn.tmall.com/attachment/icoss617334297b3958b9f8f94c9c8)

使用时，将 DTU 配置为主动连接 PulseLink 插件控制台中设置的 TCP 监听地址与端口，并确保设备能够访问该地址。保存插件控制台配置后，检查设备在线状态，再分别发送短信和语音测试，确认实际投递结果。其他型号或固件是否兼容，需要核对上述指令格式及设备回执协议。

## 投递与确认语义

- 所有通知进入共享 FIFO 队列；每台在线 DTU 都有独立 worker，同一设备同一时刻仅处理一个任务。
- 未写入设备前连接断开时，任务会回到队列；已写入设备后绝不自动重发，避免重复短信或电话。
- SMS 与 TTS ACK 会被解析为成功、失败或进度；设备断线或超时后的任务标为 `Unknown`，宿主收到 `Accepted/DtuAckPending`，不会立即重试。
- `Unknown` 任务在 5 分钟内可由同一来源 IP 的 DTU 重连后的迟到 ACK 修正为成功或失败。
- 同一来源 IP 存在待确认任务时暂停向其下发新任务，避免无任务 ID 的迟到 ACK 错配到新任务。
- TTS 协议中的 `tts busy` 是拨号进度，`TTS speack` 表示已接通并开始播放，`ready` 表示播放结束。
- 网关事件通过宿主插件日志记录，并携带投递 ID 以便与系统投递记录关联。

## 配置与系统集成

网关参数只有一个来源：**插件控制台**。短信和语音渠道实例仍然需要各创建并启用一个，以连接通知策略、收件人和模板；两种渠道均声明最多一个实例，渠道配置 JSON 应保持 `{}`。旧部署中的渠道级 DTU JSON 仅作为首次保存前的兼容性回退。

控制台可查看在线设备、设备上报日志、投递队列和历史任务；可取消尚未下发的任务，并清理已结束的任务记录。

## 安装与首次配置

在官方插件仓库根目录运行 `./Pack-Plugins.ps1`，统一构建并打包 WxPusher 与 DTU。版本化 ZIP 输出到 `artifacts/`，DTU 当前版本示例为 `pulselink.dtu-1.0.1.zip`。发布前在 PulseLink 宿主配置 `PulseLink:Notifications:Plugins:AllowedPluginIds`（环境变量 `PULSELINK_NOTIFICATION_PLUGIN_ALLOWLIST`）中允许 `pulselink.dtu`，再到“通知中心 → 插件”上传 ZIP。白名单是宿主配置，不属于插件渠道 JSON。

安装后创建并启用 `sms` 和 `voice` 两个渠道实例，将它们关联到通知策略、收件人和模板；两个实例的配置 JSON 保持 `{}`。然后打开“插件控制台”配置 TCP 监听参数并保存。首次在控制台保存前不会启动 TCP 监听；旧部署仍可在首次保存前从已启用渠道的旧配置读取兼容设置。保存后，控制台配置成为唯一设置来源。

升级插件后，确认渠道实例仍启用，并在插件控制台检查监听地址、端口、DTU 在线状态和设备上报日志。控制台也可查看投递队列与历史任务、取消尚未下发的任务、清理已结束任务记录。
